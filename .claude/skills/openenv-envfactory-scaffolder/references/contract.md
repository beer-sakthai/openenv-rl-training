# The `environment_factory` contract — full reference

TRL's `GRPOTrainer(environment_factory=...)` accepts any class that exposes
`reset()` and public tool methods. What follows is every rule the trainer
(or the OpenEnv server) enforces, with **why** each one exists so the
generated code fits the constraint instead of just tiptoeing around it.

Sourced from:
- TRL 1.9.x `grpo_trainer.py` source (the failure paths are in there)
- OpenEnv 0.4.1 `env_server/interfaces.py` (concurrency, session handling)
- `sakthai-agentic-eval-train/FINDINGS.md` (which failure modes actually bit)
- `env_simple_task.py`, `agent_tools/wrapper.py`, `agent_tools/server/sandbox_env.py`

---

## 1. The environment class

### `__init__(self)` takes no arguments

TRL instantiates one environment per generation slot in the batch:
`EnvironmentFactory()`, never `EnvironmentFactory(cfg)`. Configuration comes
from **module-level constants or env vars** — see how
`agent_tools/wrapper.py` reads `AGENT_TOOLS_URL` from `os.environ`.

### `reset(**kwargs)` receives every dataset column as a keyword argument

Except the routing control column in dict-form factories (see §Multi-env
routing below). Return a **string** to give the model its first observation,
or `None` to skip the initial hint.

**Why kwargs, not positional args:** TRL doesn't know your dataset schema
at trainer construction — it forwards every non-prompt column by name.
Positional `reset(target)` would tie the env to a specific column ordering.

### Every public method other than `reset` becomes a callable tool

- Named after the method
- Schema auto-generated by `transformers.get_json_schema` from **type hints
  + docstring**
- **Google-style docstring with a complete `Args:` block is mandatory.**
  A one-line docstring raises `DocstringParsingException` at trainer
  construction, before a single step runs. This is the single most common
  failure mode when copy-adapting from other codebases.

**Why named tools beat a generic `step(action)`:** the model reads the
docstring as the tool description. `guess(number: int)` gives the LLM a
crisp affordance; `step(action: str)` forces it to invent an action grammar
on the fly, which it will do inconsistently and GRPO cannot learn from.

### Episode state lives on `self`

Set `self.reward = 0.0` and `self.done = False` in `__init__`, mutate them
in the tool methods, and the reward function reads them back off the
instance after the episode ends. Don't stash reward in a class attribute or
a module-level dict — one env per slot, and slot-to-slot bleed will silently
break training.

### Raising an exception rejects a call

TRL catches it and feeds the exception message back to the model as the
tool result. Use this for:

- Out-of-range arguments (`raise ValueError(...)` with a message that tells
  the model what the valid range is — it can act on that feedback)
- Out-of-turn calls in multi-environment classes
- "Episode already ended" (rejects further tool use after `self.done` is set)

**Do not** silently ignore invalid input — the model won't learn from
no-op feedback.

### Cap the episode

Every environment must have a step / attempt limit (`MAX_ATTEMPTS = 10`,
`STEP_LIMIT = 15`) so a non-converging rollout terminates with a clean
`0.0` instead of looping forever. GRPO ranks within a group; a group with
one unbounded rollout wastes the whole batch.

## 2. Reward functions

### Signature

```python
def reward_func(environments, **kwargs) -> list[float]:
    return [env.reward for env in environments]
```

`environments` is the full batch of instantiated env objects — same length
as `num_generations` per prompt.

### Binary and outcome-based

Rewards are **1.0 / 0.0** and judged on the **final state**, not the path
taken. GRPO ranks within the group so only the ordering the reward
induces matters. An outcome-only reward lets the model find strategies you
didn't script; a path-scored reward locks it into whatever plan you had in
mind and starves exploration.

### Multi-environment: one reward function per env, return `None` for others

When the trainer runs several envs in the same batch (dict-form factory
or meta-class), each `reward_func` returns `None` for episodes that
belonged to another environment. TRL turns `None` into `NaN` and
aggregates each reward function over its own episodes only. Don't try to
share one reward function — the aggregation will average across incompatible
scales.

## 3. Datasets

### `prompt` must be a **list of `{role, content}` dicts**

TRL's tool-calling GRPO does `prompt[-1]["content"]`. A bare string fails
with `TypeError: string indices must be integers` on the first batch.

```python
prompts = [
    [
        {"role": "user", "content": "The task prompt goes here."}
    ]
    for _ in range(n_episodes)
]
```

### Scoring-only columns

Columns like `target` (the hidden answer) and `task` (which acceptance
predicate to use) are passed to `reset(**kwargs)` and **never shown to the
model**. This is the standard pattern for hiding the ground truth.

### Deterministic construction

Build the dataset deterministically (`target = (i * 7) % 100`), not with
`random.randint`. Reproducible runs matter for the eval-then-train loop —
`FINDINGS.md` has cases where a random dataset masked a real regression.

### Module-level exports

```python
ENVIRONMENT_FACTORY = MyEnv
REWARD_FUNCS = reward_func     # or a list, for multi-env
TRAIN_DATASET = build_dataset  # a callable, not the dataset
DEFAULT_MODEL = "Nanthasit/sakthai-context-7b-tools"
```

`train.py`'s dispatch table looks these names up by convention.

## 4. Multi-env routing

The routing column name is **not consistent across the repo** — check the
file the env is being added to before copying:

| File | Routing column |
|---|---|
| `openenv-custom-training/multi_env.py` (dict-form factory) | `environment` (TRL's convention, not forwarded to `reset`) |
| `openenv-multi-catalog-training/train_multi_env.py` (meta-class) | `env` |
| `openenv-custom-training/agent_tools/` (single env, multi-task) | `task` (forwarded to `reset` as a normal kwarg) |

Keep each file self-consistent. Don't try to unify the naming casually —
the dict-form key is special-cased by TRL (stripped before `reset`), while
the meta-class column is a normal kwarg the class reads itself.

## 5. GRPOConfig gotchas

The trainer's config accepts a lot of fields; a handful cause silent
failure or immediate crash if wrong:

- **vLLM server-mode fields are `vllm_server_host` + `vllm_server_port`.**
  `vllm_server_url` does not exist and crashes at construction. This one
  has landed on `main` multiple times.
- **`max_completion_length` caps tokens across the WHOLE multi-turn
  episode** — every generation plus every tool result, summed. Not one
  turn. Episodes truncating mid-task is the first thing to suspect when
  reward is stuck at 0; a too-small cap starves GRPO of signal entirely.
- **1 GPU → `--vllm-mode colocate`. 2+ GPUs →** `trl vllm-serve` on one,
  then `--vllm-mode server`.
- **Hard requirements** when `environment_factory` is used:
  - `transformers>=5.2.0` (GRPOTrainer raises below it)
  - `jmespath` (undocumented dep, needed for tool-response parsing)
  - a base model whose **chat template supports tool calling** —
    `sakthai-context-0.5b-merged` ships no chat template and is therefore
    not a valid base

## 6. Tier B — the sandboxed server

### The three-piece split

Mirror `agent_tools/`'s layout:

- `<name>_tools/wrapper.py` — TRL-facing class, thin, forwards to client
- `<name>_tools/server/sandbox_env.py` — task logic, owns the state,
  scores each step
- `<name>_tools/models.py` — Action / Observation dataclasses
- `<name>_tools/client.py` — HTTP shim (usually a direct copy from
  `agent_tools/client.py`; only the tool names change)

Why: the wrapper never scores anything. The **server** owns the state and
therefore owns the verdict. The wrapper's `_forward()` copies `reward` /
`done` off the observation and hands the result string back to TRL.

### Concurrency

- `SUPPORTS_CONCURRENT_SESSIONS = True` as a **class attribute** on the
  `Environment` subclass, not module-level. The server does
  `getattr(env_cls, "SUPPORTS_CONCURRENT_SESSIONS", False)` and refuses
  `max_concurrent_envs > 1` without it.
- `create_app(..., max_concurrent_envs=N)` with `N >= num_generations`,
  because GRPO opens one session per generation in the batch.

### Per-step guards (no command blocklist)

Every `_run_command` / `_write_file` / `_read_file` path must have:

- **Timeout** (`CMD_TIMEOUT_S = 10`) — a hung command blocks the whole
  session slot
- **Output caps** (`MAX_STDOUT`, `MAX_STDERR`) — a runaway `find /` fills
  the observation with noise the model can't use
- **`cwd` confined to a per-episode `tempfile.mkdtemp()`** — fresh dir per
  `reset()` so one session's artefacts don't leak into another's grading
- **Realpath escape check** — resolve the requested path and refuse
  `not p.is_relative_to(self._workdir.resolve())`. Blocks `../../etc/passwd`
  without pattern-matching on the string
- **Env stripped** to `PATH`, `HOME`, `LANG`. Don't inherit the training
  process's env — anything leaked in becomes an attack surface

There is deliberately **no** command blocklist in `_run_command`. The
policy will find a spelling you didn't block; the container is the
isolation, not the string filter.

### Recommended container flags

`USER nobody`, `docker run --network none --pids-limit 128`. The image
handles what a blocklist can't.

### Task registry pattern

Almost always the right shape: one `Environment` class handling **multiple
named tasks** keyed by a `task` column, like `sandbox_env.py`'s `TASKS`
dict. Each task has a prompt (what the model sees) and an acceptance
predicate `_accepts(task_key, workdir) -> bool` (what determines
`reward = 1.0`). Evaluated after every step.

## 7. The two-piece dataset for Tier B

The wrapper's `build_dataset` picks task keys deterministically:

```python
TASK_KEYS = ("answer_file", "count_lines", "upper_copy")
TASK_PROMPTS = {"answer_file": "...", ...}

def build_dataset(n_episodes: int = 64):
    rows, tasks = [], []
    for i in range(n_episodes):
        task_key = TASK_KEYS[i % len(TASK_KEYS)]
        rows.append([{"role": "user", "content": TASK_PROMPTS[task_key]}])
        tasks.append(task_key)
    return Dataset.from_dict({"prompt": rows, "task": tasks})
```

The `task` column is passed to `reset(**kwargs)` and forwarded to the
server as `task_key=...`. Server-side, `TASKS[task_key]` picks the prompt
and `_accepts(task_key, workdir)` scores the outcome.

## 8. Common failure modes and their symptoms

| Symptom | Cause |
|---|---|
| `DocstringParsingException` at trainer construction | Missing `Args:` block on a public method |
| `TypeError: string indices must be integers` on first batch | `prompt` is a string, not a list of dicts |
| Reward stuck at 0.0 across all rollouts | `max_completion_length` too small — episode truncates mid-task |
| Reward variance = 0, `grad_norm` = 0 | Model solves the task ~0% of the time; SFT bootstrap needed (see `FINDINGS.md`) |
| Server refuses `max_concurrent_envs > 1` | `SUPPORTS_CONCURRENT_SESSIONS` set at module level, not on the class |
| GRPO crashes at construction with vLLM error | Used `vllm_server_url` (doesn't exist); the fields are `vllm_server_host` + `vllm_server_port` |
| First tool call raises "tool not found" | Base model's chat template doesn't declare tools; use a base with tool-calling support (`sakthai-context-{1.5b,7b}-tools`, not `-merged`) |
